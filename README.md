# AI Driving Risk & Accident Severity Simulator

A graduation project combining a real machine-learning model with a small
interactive 2D driving simulator. As the driver adjusts speed and seatbelt
status, and as the environment auto-changes, a trained classifier predicts
accident severity in real time, displayed as a SAFE / MINOR RISK / HIGH RISK
dashboard.

**Read `docs/PROJECT_GUIDE.md` first** — it explains every non-obvious
decision in this project, including why several dataset features were
excluded. `docs/PRESENTATION_GUIDE.md` has a demo script and expected Q&A
for the project discussion.

---

## ⚠ Scientific disclosure (read this first)

The model was trained and evaluated on **BDRoadRisk**, a 100% **synthetic**
traffic-risk benchmark dataset — 10,000,000 GPS-based traffic-event records
generated by a probabilistic simulation, not collected from real accidents.
This project demonstrates a genuine end-to-end ML pipeline and interactive
prediction workflow; every prediction shown is real model output. But the
resulting probabilities are **not calibrated real-world accident
probabilities** — they reflect patterns in a synthetic benchmark, not
measured real-world risk. See `docs/PROJECT_GUIDE.md` for the full
explanation, including which specific features were excluded because their
values were generated *from* the target label rather than independently of
it.

## Features

- Real scikit-learn pipeline (preprocessing + RandomForestClassifier)
  trained on BDRoadRisk, with an explicit, documented leakage analysis
  driving feature selection — not "use every column and hope for the best."
- FastAPI backend exposing `/predict`, with full input validation and error
  handling.
- Flutter app with a live 2D side-view driving scene (Flame engine) whose
  environment auto-changes every 10 seconds.
- Two live user controls — **Speed** (`speed_kmh`) and **Seatbelt**
  (`seatbelt_worn`) — the original project concept, both mapped directly to
  real model features.
- Every prediction shown is a real API call to the real trained model. No
  hardcoded thresholds, no fabricated percentages.

## Architecture

```
Flutter + Flame (frontend/)
        ↓  speed slider, seatbelt toggle, auto-changing environment
FastAPI (backend/)
        ↓  POST /predict → validates input → builds feature row
Saved scikit-learn Pipeline (ml/model/risk_pipeline.joblib)
        ↓  preprocessing (impute + one-hot + scale) → RandomForestClassifier
predict_proba()
        ↓  real probability for each of 3 classes
JSON Response  { prediction, risk_label, probability, probability_percent, probabilities }
        ↓
Flutter Risk Dashboard  (SAFE / MINOR RISK / HIGH RISK + %)
```

## Dataset

**BDRoadRisk: Large-Scale GPS Traffic Accident Severity Dataset** — Mendeley
Data, DOI `10.17632/m33bsbsgx2.3`, CC BY 4.0, Dewanjee & Muntaha (Chittagong
University of Engineering & Technology).

- **10,000,000** synthetic GPS traffic-event records, 23 features + 1
  target, simulating road conditions in Dhaka and Chittagong, Bangladesh.
- **100% synthetic** — labels were generated by a context-driven
  probabilistic model, with 1.8% boundary noise injected at the
  No_Accident/Minor boundary "to reflect real-world reporting ambiguity."
  This is stated directly in the dataset's own documentation, not inferred.
- This project trains on a **500,000-row systematic sample** (every 20th
  row of the full 10M-row source CSV) — loading all 10M rows for
  development would be unnecessary and slow. The sample's class
  distribution was verified to closely match the full dataset (No_Accident
  74.35% vs 74.41% full, Minor 17.34% vs 17.30%, Major 8.31% vs 8.28%).

Two prior candidate datasets were investigated and rejected before
BDRoadRisk — see `docs/PROJECT_GUIDE.md` §2 for the full history:
1. The originally-provided dataset scored ROC-AUC ≈ 0.50 (no better than
   random) under cross-validation — statistically pure noise.
2. A real police-recorded dataset (Addis Ababa) had genuine but modest
   signal (AUC ~0.58–0.65) and no real speed or seatbelt columns, forcing
   the player controls to be replaced with unrelated substitutes. BDRoadRisk
   was chosen specifically because it restores the original speed/seatbelt
   concept with real matching columns.

**Target:** `accident_severity` — `No_Accident` / `Minor` / `Major`.

## ML pipeline

```
ml/dataset_bdroadrisk/bdroadrisk_sample_500k.csv  → the 500k-row training sample
ml/train_model.py                                  → clean → leakage analysis →
                                                       feature selection → train
                                                       3 models → select best by
                                                       CV ROC-AUC → evaluate on
                                                       held-out test set → save
ml/model/risk_pipeline.joblib                       → the saved, complete pipeline
ml/model/categories.json                            → valid category values (API validation)
ml/model/numeric_ranges.json                        → valid numeric ranges (API validation)
ml/model/fixed_context.json                         → the 12 fixed-context default values
ml/model/metrics.json                                → full evaluation results
```

**Selected model:** RandomForestClassifier (chosen over LogisticRegression
and ExtraTreesClassifier by cross-validated ROC-AUC).

**Held-out test set metrics** (100,000 rows, never used in training or
model selection):

| Metric | Value |
|---|---|
| Accuracy | 0.811 |
| Precision (macro) | 0.704 |
| Recall (macro) | 0.770 |
| F1 (macro) | 0.730 |
| ROC-AUC (one-vs-rest, macro) | 0.920 |

Full metrics, per-model CV comparison, and the confusion matrix:
`ml/model/metrics.json`. Why ROC-AUC/F1/macro-averages instead of raw
accuracy, and what these numbers mean, are explained in
`docs/PROJECT_GUIDE.md` §5.

To retrain:

```bash
cd ml
ml/.venv/bin/python train_model.py    # or: pip install -r requirements.txt; python train_model.py
```

## Flutter setup

```bash
cd frontend
flutter pub get
flutter run -d chrome     # or: flutter run -d macos / an attached device
```

The app talks to `http://127.0.0.1:8000` by default
(`frontend/lib/api/risk_api_client.dart`). Localhost configuration by
target:
- **Chrome / macOS desktop:** `127.0.0.1` works as-is (same machine).
- **Android emulator:** the emulator's loopback to the host machine is
  `10.0.2.2`, not `127.0.0.1` — change `RiskApiClient(baseUrl: ...)` in
  `frontend/lib/ui/simulator_page.dart` accordingly.
- **iOS simulator:** `127.0.0.1` works as-is (shares the host's network).

## How to run everything

1. Terminal 1: start the backend (see above) — leave it running.
2. Terminal 2: `cd frontend && flutter run -d chrome`.
3. The app fetches a prediction on load, every 10 seconds as the
   environment auto-changes, whenever the seatbelt is toggled, and (after a
   350ms debounce) whenever the speed slider settles.

## How to test the API

```bash
# Valid request — high risk
curl -X POST http://localhost:8000/predict -H "Content-Type: application/json" -d '{
  "speed_kmh": 170, "seatbelt_worn": "No", "weather_condition": "Storm",
  "road_surface": "Wet", "light_condition": "Dark_Unlit", "time_of_day": "Night"
}'
# → {"prediction":"Major","risk_label":"HIGH RISK","probability":0.44,"probability_percent":44,"probabilities":{...}}

# Valid request — safe
curl -X POST http://localhost:8000/predict -H "Content-Type: application/json" -d '{
  "speed_kmh": 45, "seatbelt_worn": "Yes", "weather_condition": "Clear",
  "road_surface": "Dry", "light_condition": "Daylight", "time_of_day": "Afternoon"
}'
# → {"prediction":"No_Accident","risk_label":"SAFE","probability":0.92,"probability_percent":92,"probabilities":{...}}

# Invalid category → 422 with the list of valid values
curl -X POST http://localhost:8000/predict -H "Content-Type: application/json" -d '{"weather_condition":"Tornado", ...}'

# Missing fields → 422 listing exactly which fields are missing
curl -X POST http://localhost:8000/predict -H "Content-Type: application/json" -d '{"speed_kmh": 60}'
```

Full category vocabulary: `ml/model/categories.json`, or `GET /categories`.
Valid numeric ranges: `ml/model/numeric_ranges.json`.

## How to run the simulator

See "Flutter setup" above. Once running:
- The 2D side-view driving scene (Flame) shows the current environment
  visually — weather, road wetness, day/night lighting.
- Speed slider (0–200 km/h) and Seatbelt toggle are the two live controls.
- The environment (weather/road/light/time-of-day) auto-cycles through 5
  predefined scenarios every 10 seconds.
- The Risk Dashboard shows SAFE 🟢 / MINOR RISK 🟡 / HIGH RISK 🔴 and the
  model's actual predicted probability.
- The "INPUT → output" strip at the bottom shows exactly what was sent to
  the model and what came back.
- Wind is shown only during the Storm scenario and is explicitly labeled
  "visual only" — it is never sent to the model (BDRoadRisk has no wind
  feature).

## Project limitations

Stated honestly, not hidden — see `docs/PROJECT_GUIDE.md` and
`docs/PRESENTATION_GUIDE.md` for full discussion:

1. **The dataset is 100% synthetic.** No real accident records were used.
   Predicted probabilities reflect patterns in a generated benchmark, not
   measured real-world risk — they must not be interpreted as calibrated
   real-world accident probabilities.
2. Several dataset features were excluded because their generation process
   makes them scientifically unsound to use:
   - `junction_type` and `visibility_km` — the dataset's own documentation
     states these were generated with distributions conditioned on the
     target label itself ("severity-driven distributions" /
     "driven by... severity class") — using them would mean the model
     partly decodes the label from a feature built *from* that label.
   - `acceleration_ms2` and `reaction_time_sec` — these describe the
     mechanics of a specific incident (how hard you braked, how fast you
     reacted, at that moment), not a pre-existing condition a real-time
     simulator could set in advance.
   - `temperature_celsius` — the dataset's own documentation labels it
     "non-predictive... Intentional noise feature."
3. Several remaining model features (`driver_experience_level`,
   `alcohol_influence`, `traffic_density`, etc.) carry real predictive
   weight but are held at fixed default values in this simulator rather
   than exposed as live controls — the game deliberately stays simple
   (just Speed + Seatbelt), so live predictions explore only a slice of the
   model's full input space. Full reasoning and default values:
   `docs/PROJECT_GUIDE.md` §4, `ml/model/fixed_context.json`.
4. This project is an **educational simulator demonstrating a real,
   working ML pipeline and interactive workflow** — not a real-world
   calibrated accident-risk predictor.
